/01 What Breaks

v0 failure modes I see every week.

No backend logic

v0 generates UI, not your API routes, database queries, or business logic. Someone still has to wire the polished frontend up to real data — and that wiring is where most of the actual bugs live.

Unrequested changes to working code

Ask for a small tweak and v0 rewrites unrelated components or files, breaking things that worked a moment ago. Small requests turn into wide blast radius.

Security hidden behind polish

Because generated components look finished, they ship without a security review. Missing input validation, exposed data, and other gaps common to AI-generated code go unnoticed because the UI looks production-ready.

Accessibility gaps

Visually correct markup that misses semantic HTML and ARIA fundamentals — fine for a demo, a liability once real users (and audits) show up.

Library and version lock-in

Generated components are tightly coupled to specific library versions and Tailwind conventions. Integrating them into an existing design system, or upgrading a dependency, breaks things in ways that aren't obvious from the diff.
